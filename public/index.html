INFER / INFERENCE RESEARCH

Models act
only when they infer.模型在推理时
才真正醒来。

A trained model is a file that sits still. Every answer it gives and every action it takes happens at inference. Infer studies that moment: how it works, why it matters, and where it goes wrong.训练好的模型只是一个静止的文件。它的每一次回答、每一个动作，都发生在推理这一刻。Infer 研究的就是这一刻：它怎么发生，为什么重要，又会在哪里出错。

01

What is inference什么是推理

1.1

Train once, infer forever.训练一次，推理无数次。

A model's life has two parts. Training grows it: months of computation that end in a single file of numbers, called parameters or weights. “8B” means 8 billion of them. Inference uses it: every time someone asks a question, the file is loaded and run. Training happens once. Inference happens every second, for as long as the model is in service.一个模型的一生分两段。训练是“养大”它：几个月的计算，最后得到一个装满数字的文件。这些数字叫参数，也叫权重；“8B”就是 80 亿个参数。推理是“使用”它：每当有人提问，就把这个文件拿出来算一遍。训练只发生一次，推理则在模型上线后的每一秒都在发生。

Words with a dotted underline explain themselves: hover or tap them.带虚线的词，悬停或点按就能看到解释。

1.2

One word at a time.一次只出一个字。

A model does not write an answer in one go. It reads everything so far, scores every possible next word, picks one, appends it, and reads everything again. A long answer is thousands of these small loops. Strictly, each step produces a token: a word, part of a word, or a punctuation mark. We call them all words here.模型不是一口气写出答案的。它读完已有的全部文字，给每一个可能的下一个字打分，挑出一个接在后面，然后从头再读一遍。一段长回答，就是几千次这样的小循环。严格地说，模型每次出的是一个 token：可能是一个字、半个词或一个标点。本站为了好读，统称“词”。

Watch the loop, or step through it.看它循环，或者一步步点。

1.3

Memory has a price.记性是有代价的。

Reading everything again would be wasteful, so the model keeps notes on what it has already read. They serve attention, the step where each new word looks back to find the parts of the text that matter most. These notes are called the KV cache. They grow with every word, and they live in the same scarce GPU memory as the model itself.每次都从头读太浪费，所以模型会给读过的内容记笔记。笔记是给“注意力”用的：每写一个新词，模型都要回头看前文里哪些地方最相关。这份笔记叫 KV cache。它每多一个字就长一点，而且和模型本身挤在同一块昂贵的显存里。

Drag the slider to lengthen the conversation.拖动滑块，把对话拉长。

1.4

From a file to a service.从一个文件，到一项服务。

Between the model file and the app you type into sits a whole stack: an inference engine that runs the math on GPUs, a scheduler that packs many users' requests together, and an API that the outside world calls. Each layer is software, and each can be fast or slow, sound or broken.从模型文件到你打字的那个应用，中间隔着一整套系统：在 GPU 上做计算的推理引擎，把许多人的请求拼在一起算的调度器，以及给外界调用的 API。每一层都是软件，每一层都可能快或慢，可靠或出错。

Hover a layer.悬停查看每一层。

That is inference: turning a file that sits still into a service that answers, one word at a time, for everyone at once.这就是推理：把一个静止的文件，变成一项同时为所有人、一个字一个字作答的服务。

02

Why inference matters为什么推理重要

2.1

Training is a bill. Inference is a meter.训练是账单，推理是电表。

Training is paid once, up front. Inference is paid every time the model is used, and the meter never stops. The more people rely on a model, the more its total cost shifts from building it to running it.训练的钱一次付清。推理的钱每用一次付一次，电表一直在走。用的人越多，一个模型的总成本就越从“造出来”转向“用起来”。

Switch between light and heavy use.切换用量的多少。

2.2

Thinking longer, answering better.想得越久，答得越好。

Since 2024, reasoning models have shown a new lever: let the model write out its thinking before it answers, and accuracy rises with how long it thinks. How smart a model is no longer depends only on training. It also depends on how much it is allowed to compute at inference.2024 年以来，推理模型带来了一根新的杠杆：让模型先把思考过程写出来再回答，想得越久，答对的概率越高。一个模型有多聪明，不再只由训练决定，也取决于推理时允许它算多少。

Give it more time to think.多给它一点思考时间。

2.3

Inference is where models touch the world.推理时，模型碰到了世界。

A model file cannot read your mail or run a command. At inference it can. Agents turn each step of inference into an action: open a page, read a file, run code, send a message. Whatever the model reads at that moment can steer what it does next.模型文件本身读不了你的邮件，也执行不了命令；推理时它可以。Agent 把每一步推理都变成一个动作：打开网页、读取文件、运行代码、发出消息。这一刻读进去的任何内容，都可能左右它下一步做什么。

Switch from chat to agent.从聊天切换到 Agent。

A model's value, its cost and its risk are all realised at the same moment: inference. That is why we study it.模型的价值、成本和风险，都在同一刻兑现：推理。这就是我们研究它的原因。

03

What makes inference hard把推理做好，难在哪

3.1

Speed: moving, not computing.效率：慢在搬，不在算。

To produce one word, the GPU has to read the entire model out of memory. The arithmetic is quick; the reading is slow. So one user's speed is capped by memory bandwidth divided by model size. The fix is to share each read: serve a whole batch of users with it, or let a small model guess several words ahead and check them all in one pass. That second trick is called speculative decoding.每生成一个字，GPU 都要把整个模型从显存里读一遍。计算本身很快，读才慢。所以一个人能得到的速度，上限大致是显存带宽除以模型大小。办法是让每次读取多干点活：一次读取同时服务一批人；或者让一个小模型先往后猜几个字，大模型读一遍就能一起检查。后一种叫投机解码。

Switch between one user, a batch, and guessing ahead.切换：一个人、一批人、先猜后验。

3.2

Storage: making it smaller.存储：把模型压小。

Each weight is usually stored in 16 bits. Store it in 8 or 4 instead, and the model shrinks by half or by three quarters. This is quantization. A smaller model fits on fewer cards and has less to move, so it also runs faster. The cost is a little precision in every number.每个权重通常用 16 位来存。改用 8 位或 4 位，模型就缩小一半或四分之三。这叫量化。模型小了，用的卡就少，要搬的数据也少，于是也跑得更快。代价是每个数字都损失了一点精度。

Change the number of bits.换一种位数。

3.3

Accuracy: faster, but still right?准确度：快了，还对吗？

Every shortcut can change the answer. Fewer bits round the numbers differently. Even with nothing compressed and all randomness switched off (temperature 0), the same question can come back different: depending on how many other requests share the batch, the GPU adds numbers up in a different order, and tiny rounding differences grow into different words. Rewrite the kernels, the small programs that carry out each step on the GPU (more in chapter 4), so the order never changes, and the answers stop drifting.每一种省事的办法都可能改变答案。位数少了，数字的取舍就不同。即使什么都不压缩、把随机性全部关掉（温度设为 0），同一个问题也可能得到不同的回答：同一批里一起算的请求数量不同，GPU 做加法的顺序就不同，微小的舍入误差最后会变成不同的字。把算子（GPU 上执行每一步计算的小程序，第四章细讲）改写成加法顺序固定不变，答案就不再漂移。

Run the same question a thousand times.把同一个问题跑一千次。

3.4

Architecture: not every part has to work.架构：不必全员上场。

Newer models are designed with inference in mind. A mixture-of-experts model splits itself into many experts and sends each word to only a few of them, so most of the model rests on every step. Others shrink the KV cache by changing how attention stores its notes. And serving systems split the work itself: reading the question and writing the answer run on separate machines.新一代模型在设计时就考虑了推理。混合专家（MoE）模型把自己分成许多“专家”，每个字只交给其中几个处理，每一步大部分参数都在休息。有的模型改造了注意力记笔记的方式，把 KV cache 压得很小。服务系统则把活本身拆开：读题和写答案，放到不同的机器上做。

Switch between the designs.切换不同的设计。

3.5

Fit: same model, different chip.适配：一块卡一个样。

A model is not tied to one chip, but every chip needs its own software. Each engine supports some chips and not others, and the same model on the same engine can run very differently from one chip to the next. Making a model run well across all of them is work of its own.模型本身不绑定某一块芯片，但每一种芯片都需要自己的软件。每个推理引擎只支持其中一部分芯片；同一个模型、同一个引擎，换一块芯片，表现可能天差地别。让一个模型在各种芯片上都跑得好，本身就是一门功夫。

Hover a cell.悬停查看每一格。

Inference research is the search for the best balance of fast, small and right, on every chip it has to run on.推理研究，就是在快、省、准之间找到最好的平衡，并让它在每一块要跑的芯片上都成立。

04

From weights to silicon从权重到芯片

4.1

Weights: a model is a pile of numbers.权重：模型就是一堆数字。

Download a model and you get files full of numbers, the weights. Llama 3 70B is about 141 GB of them, shipped as 30 files, too much for one card. So each big matrix is cut into slices and spread across several cards, which compute side by side and swap results after every layer. This is called tensor parallelism.下载一个模型，拿到的就是装满数字的文件，这些数字叫权重。Llama 3 70B 大约有 141 GB，分成 30 个文件，一块卡装不下。于是每个大矩阵被切成几片，分给几块卡并排计算，每算完一层就互相交换结果。这叫张量并行。

Change the number of cards.换一下卡的数量。

4.2

Precision: how a number is stored.精度：一个数怎么存。

Each weight is a floating-point number made of three parts: a sign, an exponent that sets how big it is, and a mantissa that sets how exact it is. Fewer bits means choosing what to give up. BF16 and FP16 both use 16 bits, but BF16 keeps the range and gives up detail, while FP16 does the opposite.每个权重都是一个浮点数，由三部分组成：符号；指数，决定它有多大；尾数，决定它有多精确。位数少了，就得决定牺牲哪一头。BF16 和 FP16 都是 16 位，但 BF16 保住了范围、牺牲了细节，FP16 正好反过来。

Store π in each format.把 π 存进每一种格式。

4.3

Kernels: where the speed is won.算子：速度在这里定胜负。

A kernel is a small program that runs on the GPU and carries out one step of the computation, such as one matrix multiplication. It is launched across thousands of threads at once, each computing a small piece of the result. A model is a chain of kernels, and the engine’s job is to call them in the right order; how fast the model runs depends mostly on how well they are written.算子（kernel）是在 GPU 上运行的一段小程序，负责完成一步计算，比如一次矩阵乘。它一启动就是成千上万个线程同时干活，每个线程算结果里的一小块。一个模型就是一串算子，推理引擎负责按顺序调用它们；模型跑多快，主要看这些算子写得好不好。

Take attention: multiply matrices, scale, mask, softmax, multiply again. Run each as its own kernel and every one reads its input from memory and writes its output back. Fuse them into one kernel, as FlashAttention does, and the data makes the trip only once.以注意力为例：矩阵乘、缩放、掩码、softmax、再一次矩阵乘。每一步单独作为一个算子跑，每个都要从显存读入、再写回显存。把它们融合成一个算子，就像 FlashAttention 那样，数据只需要来回一趟。

Count the trips.数一数来回了几趟。

4.4

Architecture: big and slow, small and fast.架构：大的慢，快的小。

An H100 chip is built from 132 SMs, and its memory comes in layers. Main memory is large but far away; the caches on the chip are fast but tiny. Tensor Cores, the units built only for matrix multiplication, sit at the top and starve if data does not reach them in time. A good kernel keeps the data in the fast layers for as long as it can.一块 H100 芯片由 132 个 SM 组成，存储分好几层：显存大，但离得远；芯片上的缓存快，但很小。最上面是 Tensor Core，专门做矩阵乘的计算单元，数据送不上来，它就只能干等。好的算子，就是让数据尽量待在快的那几层。

Hover a layer.悬停查看每一层。

4.5

NVIDIA: why it leads.英伟达：为什么领先。

Two reasons. CUDA, released in 2007, gave almost two decades of kernels, libraries and engineers a single home. And each new generation of its chips has added a smaller number format along with the hardware to compute in it. Other chips can match the silicon; to match the software they must rewrite the kernels, which brings us back to fit.原因有两个。一是 CUDA：它 2007 年发布，近二十年来的算子、库和工程师都聚在这里。二是它每一代芯片都加进一种更小的数字格式，以及直接用它计算的硬件。别家芯片的硬件可以追上，软件要追上，就得把算子重写一遍，这又回到了适配的问题。

Step through the generations.按代际一步步看。

Under every answer sits a stack of choices: how the weights are cut, how each number is stored, how the kernels are written, and what chip they run on.每一个回答底下，都压着一摞选择：权重怎么切，数字怎么存，算子怎么写，跑在哪块芯片上。

05

Where inference goes wrong推理时会出什么事

5.1

Doors left open.门没锁。

To answer questions, an inference service has to open a port. Ollama, a popular tool for running models yourself, has no login at all; it only stays safe because by default it listens to the local machine alone. Many people open it to the internet for convenience and never add a password. Over ten months, researchers counted more than 175,000 Ollama servers anyone could use, and nearly half of them could call tools.推理服务要回答问题，就得开一个端口。Ollama 是很流行的自建模型工具，它本身没有登录功能，默认只对本机开放才算安全。很多人图方便，把它开到公网上，却没有另加密码。研究者用了近十个月，在公网上数到超过 17 万个谁都能用的 Ollama 服务，其中近一半还能调用工具。

5.2

Bugs get copied too.漏洞也会被复制。

Inference engines are young software that moves fast. Researchers found the same few unsafe lines in one engine after another: code that turns data received over the network straight back into Python objects, which lets whoever sends it run code on the server. Some engines had simply copied it; one file in SGLang says “Adapted from vLLM”. The hole travelled with the code. Each publicly known hole gets a CVE number, shown under each engine.推理引擎是很年轻的软件，迭代很快。研究者在一个又一个引擎里发现了同样几行危险的代码：它把从网络上收到的数据直接还原成 Python 对象，等于让发送数据的人可以在服务器上运行代码。有的引擎是直接抄过去的，SGLang 的一个文件里就写着“Adapted from vLLM”。漏洞跟着代码一起走。图里每个引擎下面标着它的 CVE 编号。

Watch the code spread.看这段代码怎么传开。

5.3

Everything it reads is an instruction.读到的字，也是命令。

To a model, your request and the web pages, emails and files it reads are one stream of text. It cannot reliably tell orders from material. Hide a sentence where the model will read it, and you may rewrite what it does next. This is called prompt injection.对模型来说，你的要求，和它读到的网页、邮件、文件，都是同一串文字。它分不清哪些是命令，哪些只是资料。把一句话藏在模型会读到的地方，就可能改写它接下来要做的事。这叫提示词注入（prompt injection）。

Switch between what you see and what the model reads.切换“你看到的”和“模型读到的”。

5.4

Guardrails leak.护栏也会漏。

The usual fix is a guardrail: a small model in front of the big one that flags malicious input. But it can be fooled as well. In a 2025 test, researchers lightly disguised attacks, for example by hiding characters inside emoji, and several widely used guardrails let most of them through.常见的对策是加一道“护栏”：在大模型前面放一个专门识别恶意输入的小模型。可它自己也会被骗。2025 年的一项测试里，研究者把攻击文字稍加伪装，比如把字藏进表情符号里，好几款常用的护栏都放过了大部分攻击。

5.5

Someone else runs your meter.电表被别人拿去用。

Inference is billed by use. Leak an access key and strangers can call models on your account while you pay. Security researchers call it LLMjacking. At 2024 prices, they estimated a single hijacked account could burn more than $46,000 a day.推理按用量计费。密钥一旦泄露，陌生人就能用你的账户调用模型，钱由你来付。安全研究者把这叫 LLMjacking。按 2024 年的价格估算，一个被盗用的账户，一天就能烧掉超过 4.6 万美元。

Leak the key.把密钥泄露出去。

Every layer of the inference stack is a door: the port, the engine, the input, the guardrail, the bill. Each one has already been opened by someone.推理系统的每一层都是一扇门：端口、引擎、输入、护栏、账单。每一扇，都已经有人推开过。

06

Where the field stands现状与局限

6.1

How far it has come.已经走了多远。

In a few years, inference has gone from getting a model to run at all to an engineering discipline of its own: kernels that respect the memory hierarchy, engines that manage the KV cache like an operating system manages memory, models designed to be cheap to run, and chips built around ever smaller numbers.短短几年，推理从“能把模型跑起来”变成了一门独立的工程：算子学会了照顾存储层级，引擎像操作系统管理内存那样管理 KV cache，模型在设计时就为推理省钱，芯片则围绕越来越小的数字来造。

Step through the milestones.按时间一步步看。

6.2

A number means little without its settings.数字离不开设置。

Engines and chip makers each report how many words per second they deliver. But that number swings widely with how many users share a batch, how long the inputs and outputs are, and which precision is used. Two numbers measured under different settings cannot be compared, yet they often are.引擎和芯片厂商都会报出“每秒多少词”。可这个数字会随着一批有多少人、输入输出有多长、用什么精度而大幅变化。设置不同的两个数字本来没法比，却常常被放在一起比。

Change the test settings.换一种测试设置。

6.3

Fast and right are measured apart.快和准，常常分开量。

Speed benchmarks rarely check whether the answers are still right, and accuracy benchmarks rarely record how the model was served. Yet every speed-up from chapter 3 can cost some accuracy. The trade-off only shows when both are measured on the same runs.测速度的评测，很少检查答案还对不对；测准确度的评测，也很少记录模型是怎么部署的。可第三章里的每一种加速，都可能牺牲一点准确度。只有在同一批运行上把两者一起量，取舍才看得出来。

Look at one axis, then both.先只看一个轴，再两个一起看。

6.4

Few comparable numbers across chips.芯片之间，缺少对比。

Whether a model runs on a chip is documented. How well it runs is mostly reported by each vendor, on settings it chose. We found few public, reproducible comparisons of the same models across NVIDIA, AMD and domestic chips, the very choice many teams now face.一个模型能不能在某块芯片上跑，文档里查得到；跑得怎么样，大多是厂商各自报的，用的是各自挑的设置。同一批模型在英伟达、AMD 和国产芯片上的对比，我们没找到多少公开、能复现的数据，而这恰恰是很多团队正在面对的选择。

That is what Infer sets out to do: measure fast, small and right together, on real chips, with one ruler, and publish the method along with the data.这就是 Infer 要做的：在真实的芯片上，用同一把尺子，把快、省、准一起量出来，并把方法和数据一起公开。
